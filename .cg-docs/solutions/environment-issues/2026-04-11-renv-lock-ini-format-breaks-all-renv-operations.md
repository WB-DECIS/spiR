# Hand-written INI-format renv.lock blocks all renv operations

## Problem

All `renv` operations (`renv::snapshot()`, `renv::init()`, `renv::restore()`)
fail immediately with:

```
Error: Failed to parse 'renv.lock':
7:14: unexpected numeric constant
6: Package = R
7: Version = 4.1.0
                ^
```

## Root Cause

`renv.lock` is a **JSON** file. A manually-written placeholder was created in
INI/properties format, which renv cannot parse:

```ini
# WRONG — INI format, not JSON
[1]
Package = R
Version = 4.1.0

[2]
Package = data.table
Version = 1.14.8
```

renv's `renv_json_read()` is called on every operation before renv can do
anything — so even `renv::init()` (which would replace the lockfile) fails.

## Solution

Delete the invalid lockfile and let renv generate a fresh one:

```powershell
# Delete the invalid stub
Remove-Item renv.lock -Force

# Regenerate from currently installed packages
& "C:\Program Files\R\R-4.3.1\bin\Rscript.exe" -e `
  "setwd('path/to/project'); renv::snapshot(prompt = FALSE)"
```

The resulting `renv.lock` is proper JSON:

```json
{
  "R": {
    "Version": "4.3.1",
    "Repositories": [{ "Name": "CRAN", "URL": "https://cran.rstudio.com" }]
  },
  "Packages": {
    "cli": {
      "Package": "cli",
      "Version": "3.6.5",
      "Source": "Repository",
      ...
    }
  }
}
```

## Prevention

- Never manually write a `renv.lock` stub as a placeholder. Either:
  - Run `renv::snapshot()` to generate it properly from the start, OR
  - Omit the file entirely (renv is activated via `.Rprofile`, not `renv.lock`)
- If you need a placeholder to document intended dependency versions, use a
  comment in `DESCRIPTION` (`Imports:`) — that is the appropriate place.
- Commit the real `renv.lock` (generated by `renv::snapshot()`) as part of
  the initial package setup.
